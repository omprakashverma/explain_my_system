# History Search Feature Documentation

## Overview

The **History Search** feature extends the Ask API to intelligently search through tagged questions and their replies before querying the LLM. This leverages team knowledge to provide faster, more contextual answers while reducing unnecessary LLM API calls.

## Features

### 1. Question History Search
- Searches both file-scoped and repository-scoped tagged questions
- Uses word-overlap similarity algorithm for fast, dependency-free matching
- Configurable similarity thresholds (default: 0.7 for primary answer, 0.5+ for related questions)

### 2. Answer Source Differentiation
- **📚 From Team History**: Indicates the answer came from a previous team discussion
- **🤖 From AI**: Indicates the answer was generated by the LLM
- Visual badges in the UI make the source immediately obvious

### 3. Related Questions Display
- Shows up to 3 related historical questions (50-70% similarity)
- Includes original question text, author, timestamp
- Displays all replies from team members
- Helps users understand alternative perspectives on the same topic

### 4. Scope-Aware Search
- **FILE scope**: Searches tagged questions for the selected file only
- **REPOSITORY scope**: Searches all tagged questions across the repository
- Respects the same scope boundaries as the LLM query

## Technical Implementation

### Backend Components

#### 1. `HistorySearchService` (NEW)
**File**: `backend/app/services/history_search_service.py`

Provides semantic search over question history:
```python
def search_related_answers(
    repository_key: str,
    prompt: str,
    selected_file: Optional[str] = None,
    scope: str = "REPOSITORY",
) -> tuple[Optional[Dict[str, Any]], List[Dict[str, Any]]]
```

**Returns**:
- `best_match`: Most relevant historical Q&A if similarity ≥ 0.7, else None
- `related_questions`: List of related questions with 50-70% similarity

**Similarity Algorithm**:
- Uses Jaccard similarity (word overlap)
- Fast O(n) lookup without external dependencies
- Tunable thresholds for different use cases

#### 2. Updated `POST /ask` Route
**File**: `backend/app/api/routes/ask.py`

**New Flow**:
1. Receives ask request (prompt, selected_file, scope)
2. Gets repository_key via `repository_store.get_repository_key()`
3. Calls `history_search_service.search_related_answers()`
4. If best_match found with high similarity:
   - Uses historical answer as primary response
   - Sets `answer_source = "history"`
5. Otherwise:
   - Calls LLM for answer
   - Sets `answer_source = "llm"`
6. Returns all related questions regardless of source
7. Includes new response fields

#### 3. Updated Models
**File**: `backend/app/models/response_models.py`

New model classes:
```python
class HistoricalAnswerSource(BaseModel):
    question_id: int
    question: str
    username: str
    created_at: str
    replies: List[Dict[str, Any]]
    scope: str

class AskResponse(BaseModel):
    answer: str
    found: int
    selected_file: Optional[str]
    answer_source: str = "llm"  # "llm" or "history"
    source_question_id: Optional[int] = None
    related_questions: List[HistoricalAnswerSource] = []
```

## Configuration

### Similarity Thresholds
Edit `backend/app/services/history_search_service.py`:

```python
class HistorySearchService:
    def __init__(self) -> None:
        self.similarity_threshold = 0.5  # Minimum threshold for any match
        # Best match uses 0.7 threshold (in search_related_answers)
```

**Recommended Values**:
- `similarity_threshold = 0.5`: Be more inclusive with related questions
- `best_match >= 0.7`: High confidence for using as primary answer
- Adjust based on your team's query diversity

## Testing Guide

### Manual Testing Workflow

1. **Setup**: Start backend and frontend, load repository, authenticate

2. **Create baseline questions**:
   ```
   Q1 (file-scoped): "What does this authentication module do?"
   R1: "It handles user login and token generation"
   
   Q2 (file-scoped): "How is authentication implemented?"
   R2: "Uses JWT tokens with 7-day expiration"
   ```

3. **Test exact match**:
   - Ask: "What does this authentication module do?"
   - Expected: "Source: 📚 Team History" with Q1
   - Verify: Related questions include Q2

4. **Test similar match**:
   - Ask: "Tell me about the auth system here"
   - Expected: "Source: 📚 Team History" or "Source: 🤖 AI"
   - Verify: Related questions shown either way

5. **Test no match**:
   - Ask: "What are deployment configurations?"
   - Expected: "Source: 🤖 AI" (no similar history)

6. **Test repository scope**:
   - Switch to "Ask Entire Repository"
   - Ask a repository-wide question already tagged
   - Expected: Historical answer from any file

7. **Verify related questions**:
   - Confirm related questions appear below main answer
   - Check author names and timestamps display
   - Verify replies are properly nested

8. **Test with no replies**:
   - Create question with no replies
   - Ask similar question
   - Expected: Shows question text with "(No replies yet)"

## Performance Considerations

### Optimization Tips

1. **Limit related questions**: Currently limited to top 3 (configurable in code)
2. **Cache similarity scores**: Could pre-compute for large question sets
3. **Index by scope**: Already indexed by repository_key and scope
4. **Batch operations**: Search happens once per ask request

### Benchmarks (Expected)

- Small repos (< 100 questions): < 50ms
- Medium repos (100-1000 questions): < 200ms
- Large repos (1000+ questions): < 500ms

*Note: Actual performance depends on server resources and question complexity.*

## Troubleshooting

### Issue: No historical answers showing
**Solution**: 
- Verify questions exist in database: Check `note_store.db`
- Check similarity threshold isn't too high
- Ensure scope matches (FILE vs REPOSITORY)

### Issue: Too many false positives in related questions
**Solution**:
- Increase `similarity_threshold` in HistorySearchService
- Add domain-specific stop words to filter noise

### Issue: LLM still being called for obvious matches
**Solution**:
- Lower similarity threshold for best_match (currently 0.7)
- Check that repository_key is being set correctly

## Code Examples

### Using History Search Programmatically

```python
from backend.app.services.history_search_service import history_search_service

# Search for related answers
best_match, related = history_search_service.search_related_answers(
    repository_key="git:https://github.com/example/repo.git",
    prompt="How does authentication work?",
    selected_file="auth.py",
    scope="FILE"
)

if best_match:
    print(f"Found exact match: Question #{best_match['question_id']}")
    print(f"Confidence: {best_match['similarity']:.0%}")
    
for related_q in related:
    print(f"Related: {related_q['question']} ({related_q['similarity']:.0%})")
```
